# Archon + Supabase Integration Guide

This guide provides step-by-step instructions for deploying Archon AI with a self-hosted Supabase backend using Dokploy templates.

## 🎯 Overview

This integration provides:
- **Unified Database**: Archon stores all data in Supabase PostgreSQL
- **Shared Authentication**: Single login system via Supabase Auth
- **Vector Search**: Leverage Supabase's vector extensions
- **Real-time Features**: WebSocket connections via Supabase Realtime
- **Performance**: Connection pooling via Supabase Pooler
- **Security**: Row Level Security (RLS) for data protection

## 🏗️ Architecture

```
Project Domain: your-domain.com
├── Supabase Services
│   ├── API Gateway: https://api-supabase.your-domain.com
│   ├── Studio: https://supabase.your-domain.com
│   ├── Auth: https://auth-supabase.your-domain.com
│   ├── Database: PostgreSQL + Vector Extensions
│   └── Pooler: Connection Management
└── Archon Services
    ├── Frontend: https://archon.your-domain.com
    ├── Server: Internal API (via Kong Gateway)
    └── MCP: Model Context Protocol Server
```

## 📋 Prerequisites

1. **Dokploy Instance**: Running with project support
2. **Domain**: Custom domain for services
3. **Resources**: Minimum 4GB RAM, 2 CPU cores

## 🚀 Deployment Steps

### Step 1: Configure Project Variables

In your Dokploy project, set these **project-level variables**:

```bash
# Supabase Keys (auto-generated by Supabase blueprint)
SUPABASE_URL="https://api-supabase.your-domain.com"
SUPABASE_ANON_KEY="generated_during_deployment"
SUPABASE_SERVICE_KEY="generated_during_deployment"

# Shared Database Access
POSTGRES_HOST="supabase-db.supabase-project.svc.cluster.local"
POSTGRES_PASSWORD="generated_during_deployment"

# Archon Configuration
ARCHON_DB_CONNECTION="postgresql://supabase_archon_admin:password@supavisor:6543/postgres"
ARCHON_SECRET_KEY="your-secret-key-32-chars"

# AI Services
OPENAI_API_KEY="sk-your-openai-api-key"
OPENAI_API_BASE="https://api.openai.com/v1"
CRAWL4AI_URL="http://crawl4ai.your-domain.com:11235"
```

### Step 2: Deploy Supabase Blueprint

1. Deploy the **supabase** blueprint first
2. Wait for all services to be healthy (3-5 minutes)
3. Copy the generated keys from Supabase logs
4. Update project variables with actual keys

### Step 3: Deploy Archon Blueprint

1. Deploy the **archon** blueprint
2. Configure domain: `archon.your-domain.com`
3. Ensure project variables are accessible
4. Wait for services to start (2-3 minutes)

### Step 4: Verify Integration

#### Access Points:
- **Archon UI**: https://archon.your-domain.com
- **Supabase Studio**: https://supabase.your-domain.com
- **API Gateway**: https://api-supabase.your-domain.com

#### Verification Steps:
1. Open Archon UI
2. Sign up (creates Supabase user)
3. Check Supabase Studio → Authentication → Users
4. Create a project in Archon
5. Verify tables in Supabase Studio → Database → archon schema

## 🔧 Configuration Options

### Database Schema

The integration creates these tables in the `archon` schema:

```sql
-- Core Tables
archon.archon_settings           -- Configuration and API keys
archon.archon_sources           -- Knowledge base sources
archon.archon_crawled_pages      -- Document chunks with embeddings
archon.archon_code_examples       -- Code snippets with embeddings

-- Project Management
archon.archon_projects           -- AI projects
archon.archon_tasks              -- Task tracking
archon.archon_project_sources     -- Project-source relationships
archon.archon_document_versions  -- Version control
archon.archon_prompts            -- System prompts
```

### Vector Search

- **Embedding Model**: `text-embedding-3-small` (1536 dimensions)
- **Search Functions**: `archon.match_archon_crawled_pages()`, `archon.match_archon_code_examples()`
- **Indexes**: IVFFlat indexes for fast similarity search

### Authentication Flow

1. **Sign Up**: User registers via Supabase Auth
2. **Login**: JWT token issued by Supabase
3. **API Access**: Token used for Archon API calls
4. **Database Access**: RLS policies enforce data ownership

## 🔒 Security Features

### Row Level Security (RLS)

All Archon tables have RLS policies:

```sql
-- Service role (Archon backend) has full access
CREATE POLICY "Allow service role full access" ON archon.archon_projects
    FOR ALL USING (auth.role() = 'service_role');

-- Authenticated users can access their own data
CREATE POLICY "Allow authenticated users" ON archon.archon_projects
    FOR ALL TO authenticated USING (auth.uid() IS NOT NULL);
```

### API Keys Management

- **Storage**: Encrypted in `archon_settings` table
- **Access**: Only service role or user themselves
- **Rotation**: Via Archon Settings UI or direct SQL

### Network Security

- **Internal Traffic**: All services communicate via Docker network
- **External Access**: Only through Kong API gateway
- **Database**: Accessible only via Supabase Pooler

## 🚀 Performance Optimization

### Connection Pooling

- **Supabase Pooler**: Manages database connections efficiently
- **Default Pool Size**: 20 connections
- **Max Connections**: 100 per service
- **Transaction Mode**: Optimized for web applications

### Vector Search Performance

```sql
-- Optimized similarity search
SELECT * FROM archon.match_archon_crawled_pages(
  query_embedding,
  match_count := 10,
  filter := '{"category": "documentation"}'::jsonb
);
```

### Caching Strategy

- **API Responses**: Cached via Supabase edge functions
- **Static Assets**: Served via Supabase Storage
- **Database Queries**: Indexed for common access patterns

## 🔍 Troubleshooting

### Common Issues

#### 1. Connection Errors
```bash
# Check database connectivity
docker exec -it supabase-db psql -U postgres -d postgres -c "SELECT 1;"

# Verify pooler status
docker exec -it supabase-pooler curl http://localhost:4000/api/health
```

#### 2. Authentication Failures
```bash
# Check JWT secrets match
docker exec -it supabase-kong env | grep JWT_SECRET
docker exec -it archon-server env | grep SUPABASE_ANON_KEY
```

#### 3. Vector Search Not Working
```sql
-- Verify vector extension
SELECT * FROM pg_extension WHERE extname = 'vector';

-- Check Archon tables
SELECT table_name FROM information_schema.tables 
WHERE table_schema = 'archon';
```

### Log Locations

```bash
# Supabase Services
docker logs supabase-kong          # API Gateway
docker logs supabase-auth          # Authentication
docker logs supabase-db            # Database
docker logs supabase-pooler        # Connection Pooler

# Archon Services
docker logs archon-server         # FastAPI Server
docker logs archon-mcp           # MCP Server
docker logs archon-frontend       # React App
```

## 🔄 Backup and Restore

### Database Backup

```bash
# Full backup including Archon schema
docker exec supabase-db pg_dump -U postgres postgres > backup.sql

# Archon-specific backup
docker exec supabase-db pg_dump -U postgres postgres -n archon > archon_backup.sql
```

### Volume Persistence

Key Docker volumes to backup:

```bash
# Supabase data
volumes/supabase-db-data/          # PostgreSQL data
volumes/supabase-storage/           # File storage
volumes/supabase-db-config/         # Configuration

# Archon data (stored in Supabase)
# No separate volumes needed - everything in database
```
