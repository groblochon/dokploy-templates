# Glean + Supabase Integration Guide

This guide provides step-by-step instructions for deploying Glean knowledge management system with a self-hosted Supabase backend using Dokploy templates.

## 🎯 Overview

This integration provides:
- **Unified Database**: Glean stores all data in Supabase PostgreSQL with vector extensions
- **Shared Authentication**: Single login system via Supabase Auth
- **Advanced Search**: Vector similarity search + hybrid text search
- **Document Management**: File uploads, collections, and AI-powered organization
- **Real-time Features**: WebSocket connections via Supabase Realtime
- **Performance**: Connection pooling via Supabase Pooler
- **Security**: Row Level Security (RLS) for multi-tenant data protection

## 🏗️ Architecture

```
Project Domain: your-domain.com
├── Supabase Services
│   ├── API Gateway: https://api-supabase.your-domain.com
│   ├── Studio: https://supabase.your-domain.com
│   ├── Auth: https://auth-supabase.your-domain.com
│   ├── Database: PostgreSQL + Vector Extensions + Glean Schema
│   └── Pooler: Connection Management
└── Glean Services
    ├── Web App: https://glean.your-domain.com
    ├── Admin Panel: https://glean-admin.your-domain.com
    ├── Backend: Internal API (via Kong Gateway)
    ├── Worker: Background processing
    └── Vector DB: Milvus (for high-performance vector search)
```

## 📋 Prerequisites

1. **Dokploy Instance**: Running with project support
2. **Domain**: Custom domain for services
3. **Resources**: Minimum 4GB RAM, 2 CPU cores
4. **External Redis**: For background job processing

## 🚀 Deployment Steps

### Step 1: Configure Project Variables

In your Dokploy project, set these **project-level variables**:

```bash
# Supabase Keys (auto-generated by Supabase blueprint)
SUPABASE_URL="https://api-supabase.your-domain.com"
SUPABASE_ANON_KEY="generated_during_deployment"
SUPABASE_SERVICE_KEY="generated_during_deployment"

# Shared Database Access
POSTGRES_HOST="supabase-db.supabase-project.svc.cluster.local"
POSTGRES_DB="postgres"
POSTGRES_PASSWORD="generated_during_deployment"

# Redis Configuration
REDIS_HOST="redis.your-domain.com"
REDIS_URL="redis://redis.your-domain.com:6379"

# Glean Configuration
GLEAN_DB_CONNECTION="postgresql://supabase_glean_admin:password@supavisor:6543/postgres"
GLEAN_SECRET_KEY="your-secret-key-32-chars"

# AI Services
OPENAI_API_KEY="sk-your-openai-api-key"
OPENAI_API_BASE="https://api.openai.com/v1"

# Admin Configuration
ADMIN_USER="admin"
ADMIN_PASSWORD="your-secure-admin-password"
```

### Step 2: Deploy Supabase Blueprint

1. Deploy **supabase** blueprint first
2. Wait for all services to be healthy (3-5 minutes)
3. Copy the generated keys from Supabase logs
4. Update project variables with actual keys

### Step 3: Deploy Glean Blueprint

1. Deploy **glean** blueprint
2. Configure domains: 
   - `glean.your-domain.com` (main app)
   - `glean-admin.your-domain.com` (admin panel)
3. Ensure project variables are accessible
4. Wait for services to start (3-4 minutes)

### Step 4: Verify Integration

#### Access Points:
- **Glean Web App**: https://glean.your-domain.com
- **Glean Admin**: https://glean-admin.your-domain.com
- **Supabase Studio**: https://supabase.your-domain.com
- **API Gateway**: https://api-supabase.your-domain.com

#### Verification Steps:
1. Open Glean web app
2. Sign up (creates Supabase user + Glean profile)
3. Check Supabase Studio → Authentication → Users
4. Verify Glean user profile created
5. Check Supabase Studio → Database → glean schema

### Vector Search Architecture

- **Dual Storage**: PostgreSQL (structured data) + Milvus (vectors)
- **Embedding Model**: `text-embedding-3-small` (1536 dimensions)
- **Search Types**: Vector similarity, hybrid search, text search
- **Performance**: Optimized with Milvus for large-scale vector operations

```sql
-- Vector similarity search
SELECT * FROM glean.search_documents(
  query_embedding,
  match_count := 10,
  collection_filter := 'collection-uuid'
);

-- Hybrid search (vector + text)
SELECT * FROM glean.hybrid_search_documents(
  query_text := 'machine learning',
  query_embedding,
  match_count := 10
);
```

1. **Sign Up**: User registers via Supabase Auth
2. **Profile Creation**: Glean profile automatically created in `glean.glean_users`
3. **Login**: JWT token issued by Supabase
4. **API Access**: Token used for Glean API calls
5. **Database Access**: RLS policies enforce data ownership and collection permissions

## 🔒 Security Features

### Row Level Security (RLS)

All Glean tables have comprehensive RLS policies:

```sql
-- Users can only access their own data
CREATE POLICY "Allow authenticated users to manage own data" ON glean.documents
    FOR ALL USING (author_id = (
        SELECT id FROM glean.glean_users 
        WHERE supabase_user_id = auth.uid()
    ));

-- Public access to published documents
CREATE POLICY "Allow public read access to published documents" ON glean.documents
    FOR SELECT USING (is_published = TRUE);

-- Collection-based permissions
CREATE POLICY "Allow access to collection documents" ON glean.documents
    FOR SELECT USING (collection_id IN (
        SELECT id FROM glean.collections 
        WHERE is_public = TRUE OR created_by = (
            SELECT id FROM glean.glean_users 
            WHERE supabase_user_id = auth.uid()
        )
    ));
```

### Multi-Tenant Isolation

- **User Data**: Each user sees only their own documents and collections
- **Shared Collections**: Public collections for knowledge sharing
- **Team Collaboration**: Collection-based sharing with fine-grained permissions
- **API Keys**: Encrypted storage in database with user-specific access

### Network Security

- **Internal Traffic**: All services communicate via Docker network
- **External Access**: Only through Kong API gateway
- **Database**: Accessible only via Supabase Pooler
- **Vector DB**: Separate Milvus cluster for performance

## 🔍 Troubleshooting

### Common Issues

#### 1. Connection Errors
```bash
# Check database connectivity
docker exec -it supabase-db psql -U postgres -d postgres -c "SELECT 1;"

# Verify pooler status
docker exec -it supabase-pooler curl http://localhost:4000/api/health

# Check Glean backend connection
docker exec -it glean-backend curl http://localhost:8000/health
```

#### 2. Vector Search Not Working
```sql
-- Verify vector extension
SELECT * FROM pg_extension WHERE extname = 'vector';

-- Check Glean tables
SELECT table_name FROM information_schema.tables 
WHERE table_schema = 'glean';

-- Test embedding generation
SELECT COUNT(*) FROM glean.documents WHERE embedding IS NOT NULL;
```

#### 3. Authentication Failures
```bash
# Check JWT secrets match
docker exec -it supabase-kong env | grep JWT_SECRET
docker exec -it glean-backend env | grep SUPABASE_ANON_KEY

# Verify user profile creation
docker exec -it supabase-db psql -U postgres -d postgres -c "
SELECT COUNT(*) FROM glean.glean_users;
"
```

### Log Locations

